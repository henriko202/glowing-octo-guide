## Why this matters

The monorepo ships **mismatched versions of the two libraries that span the front/back contract**:

- `convex`: `app` and root are on `^1.41.0`, but the **backend `convex/` is on `^1.41.0`'s
  predecessor `^1.33.1`** — the Convex client the app loads is newer than the server runtime/codegen
  the backend is pinned to.
- `vitest`: `app` is on `^3.2.6` (a **major** behind) while `convex` is on `^4.1.0` and root on `^4.1.9`.

Same-major Convex is usually compatible, but the skew is a latent source of type/runtime surprises and
makes "which version are we actually on?" ambiguous. Aligning removes the ambiguity.

## Steps

### Step 1: Bump `convex` in the backend

Edit `convex/package.json`: `"convex": "^1.33.1"` → `"convex": "^1.41.0"`. Run `pnpm install`.
**Verify**: `pnpm install` exits 0; `convex` resolves to a single 1.41.x across the workspace
(`pnpm why convex` shows no split majors).

### Step 2: Regenerate Convex generated types (repo root only)

The backend's `convex/_generated/` is committed and was generated by the old version. From the **repo
root**, run `npx convex codegen` (or `npx convex dev --once`) to regenerate it against 1.41.
**STOP** if this command requires a deployment/login the executor doesn't have (it connects to a Convex
dev deployment). In that case: leave the version bump in place, note that **the user must run
`npx convex dev` from the repo root to regenerate `convex/_generated/`**, and continue to step 4 to
report whether types still check out against the committed `_generated/`.

### Step 3: Align `vitest`

Edit `app/package.json`: `"vitest": "^3.2.6"` → `"vitest": "^4.1.9"`. (Optionally bump
`convex/package.json` `vitest` `^4.1.0` → `^4.1.9` to match exactly.) Run `pnpm install`.

### Step 4: Verify everything

Run `pnpm -r test` (or `pnpm verify` if 001 landed). Run `pnpm --filter app exec tsc --noEmit` and the
convex typecheck.
**Verify**: all tests pass; typechecks exit 0.
**STOP** if the Vitest 3→4 bump breaks `app` tests in a way that needs test-API migration (config
shape, deprecated matchers) beyond a trivial fix — report the failing output and the Vitest 4 migration
note rather than rewriting many tests.
