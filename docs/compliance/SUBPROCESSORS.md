## Maintenance

- This list must be kept current. Any addition of a new sub-processor requires a signed DPA and an update to this
  document **before** the processing begins.
- DPA links marked `[bracketed]` must be filled in by the legal/compliance team before this document is published.
- Review this list at least annually or whenever the infrastructure or third-party service landscape changes.

> **Human action required:**
>
> - Fill all `[bracketed]` DPA links with actual URLs.
> - Fill `[region]` for Railway with the actual deployment region.
> - Confirm a signed DPA is in place with each sub-processor before launch.
> - Assess whether UK IDTA addenda are required for UK-resident users in addition to EU SCCs.
> - **AI inference (OpenRouter):** execute OpenRouter's DPA and confirm its zero-data-retention / no-training
    > terms (and that they flow down to the providers it routes to) in writing. Routing is constrained in code to
    > `zdr` + `data_collection: "deny"` (cheapest qualifying provider) in `convex/ai/openrouter.ts`, but is **not
    > pinned to a provider or region** — if in-region processing is required, add OpenRouter region/provider
    > constraints (e.g. `provider.only` / region routing) and update this list.
